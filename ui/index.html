회의에서 결정한 내용을 작업자가 바로 이해할 수 있는 실행 계약으로 정리합니다.

기존 Change
불러오는 중…

1 · 변경 목표

이번 회의에서 해결할 한 가지 결과는 무엇인가요?

기술 구현보다 사용자가 경험할 변화를 먼저 적으세요.

2 · 범위와 성공 기준

무엇을 하고, 무엇을 하지 않을지 합의하세요.

각 항목은 한 줄씩 입력합니다. 비목표가 있어야 회의 중 범위가 커지지 않습니다.

영향받는 서비스

Root에 이미 등록된 서비스만 선택할 수 있습니다.

3 · 작업 분담

누가 어떤 결과를 책임지나요?

기술 식별자와 브랜치는 자동으로 만들어집니다.

아직 작업이 없습니다. 회의에서 합의한 첫 작업을 추가하세요.

4 · 서비스 간 약속

서로 다른 작업자가 공유해야 할 약속이 있나요?

API, 이벤트, 데이터 형식처럼 서로의 구현을 추측하지 않게 만드는 기준입니다.

5 · 검토와 저장

회의 결과를 저장하기 전에 확인하세요.

검증 통과는 사람의 승인을 의미하지 않습니다.

계획 검토를 실행하면 차단 항목과 생성 파일이 여기에 표시됩니다.

새 파일로 추가될 변경 내용입니다.
